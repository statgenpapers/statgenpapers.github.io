# StatGen Papers

<https://statgenpapers.github.io> lists about 25 new statistical genetics papers each month.
Visitors upvote papers and add ones the list missed; the ranking updates live. It costs $0 to
run and needs no monthly work. The original requirements are in [`docs/spec.md`](docs/spec.md);
the design decisions and their evidence are in [`docs/PLAN.md`](docs/PLAN.md).

## How it works

1. **Monthly run.** On the 3rd of each month, `.github/workflows/monthly.yml` runs
   `python -m pipeline`. It fetches the previous month's pool (about 2,000 papers from the
   journals and preprint categories in `config/sources.toml`), removes duplicates, scores every
   paper, writes the top 25 to `site/data/`, commits, and deploys `site/` to GitHub Pages.
2. **Scorer.** A static text embedding of title and abstract (`potion-base-32M`) plus the venue,
   through the logistic-regression weights in `model/weights.json`. The site's About page shows
   how well it works and where it falls short; `dev/backtest/` holds the code behind those numbers.
3. **Site.** `site/` is plain HTML, CSS and JavaScript. Upvotes and visitor-added papers live in
   Firebase Firestore behind an anonymous sign-in, so nobody logs in. `firebase/firestore.rules`
   lets a browser change only its own vote and its own added papers.
4. **Learning from votes.** Each monthly run first reads all votes and saves them in
   `data/votes/` (ids hashed, names dropped). Once 30 listed papers have an upvote, it fits a
   correction to the weights and scores with weights plus correction.

## The four-column table

Every list is also a table with the columns `Journal`, `Short Name`, `Title`, `URL`, which pastes
straight into a spreadsheet:

1. `site/data/YYYY-MM.tsv`, written by each run (also printed in the run log).
2. **Copy table** on the site, which copies the list as shown, including added papers and the current order.

The short name is `Journal_FirstAuthor_Year_Keyword`. It is generated by `short_name` in
`pipeline/output.py` and, for papers added on the site, by `shortName` in `site/app.js`.

## Trigger a run by hand

1. On GitHub: **Actions → Monthly list and deploy → Run workflow**, with a month such as
   `2026-09`. Leave it empty for the previous month.
2. From a shell: `gh workflow run monthly.yml -R statgenpapers/statgenpapers.github.io -f month=2026-09`.
3. Locally: `uv run python -m pipeline --month 2026-09`, with the key in `OPENALEX_API_KEY`
   (see [`docs/setup.md`](docs/setup.md)). Then commit `site/data/` and `data/votes/` and push.

Running a month again replaces its list. Votes are kept, because they are stored per paper.

## Change the sources

Edit `config/sources.toml` and push. It holds the journals (name and ISSN), the preprint servers
and categories, the junk-title patterns, and the list size. A new venue is scored on text alone
until the weights are retrained.

## Add papers

1. **One paper:** click **Add a paper** on the site and type the journal, title and URL. To remove
   someone else's addition, delete its document under `months/YYYY-MM/submissions` in the Firebase console.
2. **Teach the scorer** (this replaces the spec's seed list). The scorer is a classifier fitted to
   a labelled pool, not a list of seeds. It needs two private files under `handoff/data/`, which
   are never committed: every candidate of the training months (`pool-*.jsonl.gz`) and the picks
   (`sheet-picks.csv`). To retrain:

   ```bash
   # optional: add a month's candidates, then append them to the pool file and the new picks to the CSV
   uv run python -m pipeline --month 2026-11 --pool-out new-pool.jsonl
   uv run --group train python dev/backtest/prep.py   # label the pool
   uv run --group train python dev/train.py           # backtest check, then model/weights.json
   git commit model/weights.json -m "Retrain weights" && git push
   ```

   `dev/train.py` embeds through the same code as the monthly run and repeats the rolling backtest
   before it writes the weights.

## One-time setup

All of this is done for the live site; [`docs/setup.md`](docs/setup.md) has the details.

1. **GitHub:** a public repository with Pages set to deploy from Actions, and the Actions secret `OPENALEX_API_KEY`.
2. **OpenAlex:** a free account and API key.
3. **Firebase** (free Spark plan, no card): a project with Anonymous sign-in and Firestore, the
   rules in `firebase/firestore.rules` published, and its web configuration in `site/config.js`.

## Checks

```bash
uv run pytest                                        # pipeline: dedupe, ids, table rows, scoring, vote correction
cd firebase && npm install && npm test               # security rules, in the local emulator
node firebase/live-check.mjs                         # security rules of the live project
uv run --with playwright python dev/site_check.py    # two browsers voting and adding a paper, live (one-time browser install: see the file)
python3 -m http.server -d site 8000                  # preview the site
```

## Layout

| Path | What |
|---|---|
| `config/sources.toml` | Sources, junk patterns, list size, vote-learning settings |
| `pipeline/` | Monthly pipeline: `fetch`, `dedupe`, `score`, `votes`, `output` |
| `model/weights.json` | Lab weights of the scorer |
| `site/` | The website; `site/data/` holds one `.json` and `.tsv` per month |
| `data/votes/` | Monthly snapshots of votes and added papers |
| `firebase/` | Firestore security rules, their tests, the live check |
| `dev/` | Local only: `train.py`, `backtest/`, `site_check.py` |
| `tests/` | Pipeline unit tests |
